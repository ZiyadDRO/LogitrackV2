# Prophet's wheel ships a TRIMMED cmdstan tree (the compiled prophet_model.bin, no
# makefile) and only asks for `cmdstanpy>=1.0.4`. cmdstanpy 1.3.0 (2025-10-20) made
# validate_cmdstan_path() reject a cmdstan directory without a makefile, so a fresh
# install resolves to 1.3.0 and every Prophet() raises before it is built. Prophet
# catches that ValueError in _load_stan_backend and never re-raises, so what you
# actually see is the misleading `AttributeError: 'Prophet' object has no attribute
# 'stan_backend'` — which is why this looked like a broken install rather than a pin.
# Verified: 1.2.5 fits; 1.3.0 does not. Revisit when prophet ships its own upper bound.
